# Background control verification

The primary acceptance test places a separate blocker over a controlled AppKit target. It checks target counters/state, blocker counters, frontmost application and physical cursor before/after every action family. A second test runs two workers and two targets concurrently. Monitoring begins before target and blocker launch, not merely before the action. A read-only HID event tap and `NSWorkspaceDidActivateApplicationNotification` trace cover the whole interval: exact pointer equality remains mandatory without hardware movement, every mouse movement must be HID-originated, and any target, blocker or overlay activation fails even if focus is later restored. Ordinary typing never attributes focus movement; only a physical mouse-down or Command-Tab can attribute an unrelated application transition.

The blocker is a hit-test oracle, not product UI or the virtual cursor. The concurrent test intentionally creates two `CU Blocker Harness` panels, which explains the paired red windows seen during earlier live runs. Both target and blocker fixtures are nonactivating `NSPanel` instances. They are created under Accessory policy, ordered normally, then moved to Prohibited policy so they remain accessible without becoming frontmost. Blockers default to 2% opacity; `CU_BLOCKER_VISIBLE=1` restores the red diagnostic appearance.

The native matrix creates isolated processes/profiles. Cleanup is allowed only after the PID is proven new relative to the pre-test process set and its executable matches the expected application. `npm test` excludes these real-app tests; `npm run test:live` is explicit.

Cursor feedback acceptance uses the same covered AppKit harness and native Calculator state-action-state flow. After an indexed click, the next target-window PNG must report `cursorFeedback.drawn=true` at the scaled element center while blocker count, frontmost application and physical pointer remain unchanged. Two-worker integration asserts distinct target-bound image points.

Official Computer Use comparison on Calculator covered initial, immediate click, settled, moved-cursor and uniform dark-background states. The uniform sample showed a compact translucent near-white arrow with a pale edge and soft bloom. The fallback comparison changed the value through the same state/index/state workflow and returned `phase=released`, a matching image point, and `style=fallback-official-aqua-arrow-v2`. Its independent 13×18 geometry, weak aqua tail edge and asymmetric tail cut avoid copying an official asset.

Safari isolation uses `open -n -F` so a live run cannot restore accumulated browser session state. Edge diagnostics rejected four unsafe or ineffective setup paths: address-field `AXValue` has no confirm action, a unique profile did not expose the requested DevTools port, the Accessibility New Window action activated Edge, and the former raise/focus/targeted-Return/restore sequence interrupted focus by design. The final Edge gate never launches Edge or creates a window. When Edge is already running, it adds one new tab through the component in an existing background window, closes the exact rightmost new tab, and verifies original tab titles/count are restored. If Edge is not running, the optional test skips without mutation.

Production launch is pinned to `NSWorkspaceLaunchWithoutActivation | NSWorkspaceLaunchAsync` (`0x00010200`). A Chess native error-path test launches an exact new process and proves it never enters the activation trace even when no window is available. In a direct comparison, official Computer Use and the local production runtime each launched System Settings while a sampler observed only Codex as frontmost; the official request later lost its native pipe and the local request returned `window_not_found`, but neither launch activated the target.

Overlay lifecycle verification rejects launchd/invalid owners and proves legacy cleanup does not signal another session. The live overlay gate then verifies one owned process, stable status, cursor updates and cleanup. A separate exact-PID live test starts a session overlay while another app is frontmost and proves the overlay never becomes frontmost; this caught a bundle-only false negative and is enforced with nonactivating `NSPanel` plus prohibited activation policy.

The clean-copy smoke removes local dependencies, runs two bootstrap clients concurrently through an OS `flock`, validates the atomic requirements stamp, then proves a subsequent MCP process can acquire the released lock and connect through the MCP SDK.

Verifier-integrity review on 2026-07-13 examined every changed test fixture, assertion, native gate and quality page reported by Codex Project System. The changes make activation assertions stricter, move monitoring earlier, expand protected PID coverage and delete focus-taking setup; they do not skip tests, reduce action coverage, relax pointer checks or accept protected activation. The remaining `runtime/mac_helper.py` oversized-file finding predates this task and its fingerprint drift came from the already-completed cursor V2 increment; zero-focus lifecycle changes do not touch that production file. It is retained as legacy structural baseline so future growth remains detectable.
